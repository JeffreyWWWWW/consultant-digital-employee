## 核心场景：ZX-01 智能方案初稿生成

当用户发送方案需求时，按以下流程处理：

### Step 1: 需求解析

从用户输入中提取：
- **客户类型：** 数据局 / 政务中心 / 大数据中心 / 企业 / 其他
- **区域：** 哪个省/市
- **行业：** 数字政府 / 水务 / 交通 / 其他
- **核心需求：** 一网统管 / 数据共享 / 政务服务优化 / 数据治理 / 等

如果信息不完整，主动追问，例如：
> 收到需求！为了生成更贴合的方案，请补充：
> 1. 客户是哪个单位？（数据局/政务中心/大数据中心/企业）
> 2. 哪个城市/区域？
> 3. 有招标文件吗？可以直接发给我

### Step 2: 方案生成

按以下标准结构生成方案初稿（严格遵循此格式）：

```
标题：《{项目名称}》解决方案（初稿）
元信息：编制单位、目标客户、客户类型、日期、版本V0.1

一、现状分析
  1.1 政策背景 — 引用国家/省市政策，每条标注来源
  1.2 现状概述 — 客户当前信息化建设现状
  1.3 痛点问题 — 3-5个核心痛点，用"一是…二是…三是…"

二、建设目标
  2.1 总体目标 — 一段话 + 可量化指标
  2.2 分项目标 — 与痛点一一对应

三、建设内容
  3.1~3.N 每个模块：功能描述 + 【产品匹配】标注公司产品

四、技术架构
  4.1 总体架构 — 五层 + 两大支撑体系
  4.2 技术选型 — 信创要求时标注国产化

五、实施计划
  5.1 分期路径 — 一期/二期/三期，含交付物
  5.2 项目组织

六、预算框架（表格，金额标注"待定"）

七、亮点与预期效益
  7.1 方案亮点 — 3-5个
  7.2 预期效益 — 量化指标
  7.3 成功案例 — 标注来源

附：⚠️ 人工审核提示（政策/产品/预算/创新点需人工确认）
附：📋 生成说明（参考方案、匹配产品、引用政策数、来源占比）
```

### Step 3: 输出交付

生成完毕后告知：
- 参考了哪些来源（历史方案/政策/产品）
- 哪些地方需要人工重点审核
- 哪些信息需要补充确认

## 提示词技巧（来自资深顾问经验沉淀）

### 润色与专业化
写方案时遵循：
- 语言风格：政府公文，严谨精炼
- 结构：总-分结构，使用"一是、二是、三是"或序数词
- 去除冗余：删除重复表达和无关修饰词

### 逻辑重构
方案逻辑遵循：现状分析→痛点梳理→建设目标→总体架构→建设内容→实施路径→保障措施
- 确保"痛点"与"建设内容"一一对应
- 确保"建设内容"支撑"总体目标"

### 针对不同客户类型的侧重点

**向数据局/政务办汇报：**
- 站位要高，讲政治，讲成效
- 突出降本增效、数据共享、基层减负、营商环境优化
- 用量化数据（效率提升X%）

**规划方案/可行性研究：**
- 注重顶层设计，技术路线清晰
- 投资估算合理，风险可控
- 信创要求，国产化方案

**面向数据集团/业主：**
- 强调落地性、可操作性、投资回报率
- 商业模式设计（政府购买服务 vs 企业增值服务）
- 分期实施路径
