# 质量检查清单

方案初稿生成后，按此清单逐项检查。

## 一、结构完整性

- [ ] 标题格式：《项目名称》解决方案（初稿）
- [ ] 建设情况汇报标题无重复词，如不得出现“建设建设情况”
- [ ] 元信息完整：编制单位、目标客户、客户类型、日期、版本
- [ ] 第一章：现状分析（含政策背景、现状概述、痛点问题）
- [ ] 第二章：建设目标（含总体目标、分项目标）
- [ ] 第三章：建设内容（分模块，含产品匹配标注）
- [ ] 第四章：技术架构（含总体架构、技术选型）
- [ ] 第五章：方案亮点与预期效益（含亮点、效益）
- [ ] 第六章：成功案例参考
- [ ] 默认未生成实施计划、项目组织和预算框架；如出现，必须是用户明确要求的扩展章节
- [ ] 附录A：人工审核提示
- [ ] 附录B：生成说明
- [ ] 附录C：来源清单
- [ ] 建设情况汇报包含“建设总体概况、场景建设成效、下一步工作计划、结尾”
- [ ] 建设情况汇报场景来自用户材料、图片OCR、需求附件、知识库或联网检索结果；未把候选场景清单机械写成固定正文

## 二、逻辑一致性

- [ ] 痛点数量 = 分项目标数量 = 建设模块数量（一一对应）
- [ ] 每个痛点在建设内容中有对应解决方案
- [ ] 建设内容支撑总体目标
- [ ] 扩展章节如启用，必须与建设模块对应，且表述为项目需求阶段建议或待确认口径

## 三、内容准确性

- [ ] 政策引用标注了来源（政策名称、发文单位、时间）
- [ ] 无虚构的政策文号
- [ ] 产品名称与公司产品清单一致
- [ ] 无虚构的产品能力
- [ ] 不确定内容标注了"待确认"或"待人工补充"
- [ ] 量化指标合理（不夸大、不虚构）
- [ ] 示例数据已逐项标注“示例数据，待人工确认”，并在正文添加 Word 批注
- [ ] 总体概况包含覆盖范围、终端数量、事项覆盖率、服务人次、时限压缩、满意度等指标位
- [ ] 正文中的待人工核查、待人工确认、待人工补充、待联网核验、待核验原文、待确认、待补充内容均已添加 Word 批注；附录A/B/C不添加批注

## 四、检索与匹配执行

- [ ] 已执行 Tavily/联网检索政策依据
- [ ] 已执行 Tavily/联网检索行业资料、统计数据或标准规范
- [ ] 地方平台名称、服务品牌、AI助手名称等已优先通过材料或联网检索核验；无法确认的已标注待人工确认，正文中添加批注
- [ ] 每一个成功案例均已执行联网检索或案例库检索
- [ ] 产品能力已优先匹配产品库；无法确认的产品已标注 `待确认`
- [ ] 案例库可用时已优先匹配案例库；不可用时已使用联网检索补足来源
- [ ] 检索失败项已在附录B或交付说明中说明失败降级状态

## 五、语言风格

- [ ] 全文无"综上所述"、"总而言之"
- [ ] 全文无"全方位保障"、"一站式服务"
- [ ] 全文无"赋能千行百业"类空话
- [ ] 全文无"作为AI"、"仅供参考"
- [ ] 无 emoji 符号
- [ ] 符合政府公文风格
- [ ] 使用了"一是、二是、三是"或序数词结构
- [ ] 场景成效和下一步计划采用“加粗小标题 + 正文说明”格式，如“一是高频事项智能秒批。……”

## 六、来源追溯

- [ ] 政策、行业资料、成功案例均在“附录C：来源清单”中列明链接或核验状态
- [ ] 附录C保留“待核查项清单”，列出示例数据、待确认平台名称、待核验政策依据等人工复核项
- [ ] 正文未内嵌 URL、长链接或 `[来源：...]` 标记
- [ ] 无来源链接的政策和案例已标注 `[待联网核验]` 或 `待核验原文`
- [ ] 交付说明中说明政策和案例来源详见“附录C：来源清单”

## 七、客户适配

- [ ] 写作侧重点符合客户类型
- [ ] 区域信息准确体现在政策引用中
- [ ] 地方化平台、移动端、AI助手名称已体现；无法确认的名称已标注待人工确认，正文中添加批注
- [ ] 行业术语使用正确
- [ ] 未泄露其他客户信息

## 八、审稿修正

- [ ] 已根据本清单生成 `review_notes`
- [ ] 已根据审稿结果修正初稿 JSON
- [ ] 修正后的 JSON 再用于 Word 输出
