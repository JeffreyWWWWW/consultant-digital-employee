# 质量检查清单

方案初稿生成后，按此清单逐项检查。

## 一、结构完整性

- [ ] 标题格式：《项目名称》解决方案（初稿）
- [ ] 元信息完整：编制单位、目标客户、客户类型、日期、版本
- [ ] 第一章：现状分析（含政策背景、现状概述、痛点问题）
- [ ] 第二章：建设目标（含总体目标、分项目标）
- [ ] 第三章：建设内容（分模块，含产品匹配标注）
- [ ] 第四章：技术架构（含总体架构、技术选型）
- [ ] 第五章：实施计划（含分期路径、项目组织）
- [ ] 第六章：预算框架（表格，金额标"待定"）
- [ ] 第七章：亮点与预期效益（含亮点、效益、案例）
- [ ] 附录A：人工审核提示
- [ ] 附录B：生成说明
- [ ] 附录C：来源清单

## 二、逻辑一致性

- [ ] 痛点数量 = 分项目标数量 = 建设模块数量（一一对应）
- [ ] 每个痛点在建设内容中有对应解决方案
- [ ] 建设内容支撑总体目标
- [ ] 实施计划覆盖所有建设模块
- [ ] 预算表覆盖所有建设模块

## 三、内容准确性

- [ ] 政策引用标注了来源（政策名称、发文单位、时间）
- [ ] 无虚构的政策文号
- [ ] 产品名称与公司产品清单一致
- [ ] 无虚构的产品能力
- [ ] 不确定内容标注了"待确认"或"待人工补充"
- [ ] 量化指标合理（不夸大、不虚构）

## 四、语言风格

- [ ] 全文无"综上所述"、"总而言之"
- [ ] 全文无"全方位保障"、"一站式服务"
- [ ] 全文无"赋能千行百业"类空话
- [ ] 全文无"作为AI"、"仅供参考"
- [ ] 无 emoji 符号
- [ ] 符合政府公文风格
- [ ] 使用了"一是、二是、三是"或序数词结构

## 五、来源追溯

- [ ] 政策、行业资料、成功案例均在“附录C：来源清单”中列明链接或核验状态
- [ ] 正文未内嵌 URL、长链接或 `[来源：...]` 标记
- [ ] 无来源链接的政策和案例已标注 `[待联网核验]` 或 `待核验原文`
- [ ] 交付说明中说明政策和案例来源详见“附录C：来源清单”

## 六、客户适配

- [ ] 写作侧重点符合客户类型
- [ ] 区域信息准确体现在政策引用中
- [ ] 行业术语使用正确
- [ ] 未泄露其他客户信息
