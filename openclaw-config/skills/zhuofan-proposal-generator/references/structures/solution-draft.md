# 项目需求阶段解决方案初稿结构


项目需求阶段初稿重点服务政务服务中心客户沟通、需求澄清和方案深化前置判断，默认回答“为什么做、现状痛点是什么、建议做什么、需求边界是什么、价值是什么、依据和案例是什么”。不默认承诺实施排期、项目组织、预算报价。

### 元信息区

```
《{项目名称}》解决方案（初稿）

编制单位：卓繁信息集团股份有限公司
目标客户：{客户单位全称}
客户类型：{政务服务中心/数据局/大数据中心/数据集团/企业}
项目阶段：项目需求阶段
编制日期：{YYYY年MM月DD日}
版  本：V0.1（AI辅助生成初稿）
```

### 第一章：现状分析

#### 1.1 政策背景

**写作要求：**
- 按国家级 → 省级 → 市级三级梳理相关政策
- 每条政策标注：政策全称、发文单位、发文时间/文号
- 说明政策对本项目的指导意义

**候选政策来源：**
- 国家层面：根据项目主题选择数字政府、政务服务、政务大数据、数据要素、城市运行等相关政策，不得固定套用。
- 省级层面：按项目所在地和主题检索数字政府建设规划、政务服务改革、公共数据管理、数据条例等文件。
- 市级层面：按客户需求检索智慧城市、一网统管、政务服务大厅、数据共享、基层治理等相关方案或管理办法。

**格式示例（仅在项目主题匹配并能核验来源时使用）：**
```
2023年2月，中共中央、国务院印发《数字中国建设整体布局规划》，明确提出
"到2025年，基本形成横向打通、纵向贯通、协调有力的一体化推进格局"，
为{区域}数字政府建设指明了方向。来源详见附录C。
```

#### 1.2 现状概述

**写作要求：**
- 客观描述目标客户当前信息化建设水平
- 已有的信息化系统和平台
- 取得的阶段性成果
- 如无具体信息，按行业通用水平描述，并在附录B“内容来源说明”中提示需人工审核

#### 1.3 痛点问题

**写作要求：**
- 列出 3-5 个核心痛点
- 使用"一是……二是……三是……"句式
- 每个痛点都必须在第三章"建设内容"中有对应的解决方案
- 痛点描述要具体，避免空泛

**格式示例：**
```
一是数据孤岛问题突出。各部门业务系统独立建设，数据标准不统一，
  跨部门数据共享交换困难，导致"数据多跑路、群众少跑腿"难以落地。

二是城市运行管理缺乏统一平台。各条线管理系统分散，事件处置流程
  不畅，跨部门协同效率低，缺少统一的城市运行态势感知能力。

三是……
```

### 第二章：建设目标

#### 2.1 总体目标

**写作要求：**
- 一段话概括项目整体建设目标
- 包含可量化的指标（效率提升XX%、覆盖率达XX%等）
- 体现与国家/省级政策的呼应

#### 2.2 分项目标

**写作要求：**
- 与 1.3 痛点一一对应
- 每个痛点对应一个建设目标
- 目标可衡量、可检验

### 第五章：方案亮点与预期效益

#### 5.1 方案亮点
- 列出 3-5 个差异化亮点
- 突出技术创新、管理创新、模式创新

#### 5.2 预期效益
- 量化指标：效率提升、覆盖率、成本节约
- 社会效益：群众满意度、政务透明度
- 经济效益：可写投资价值或资源节约方向，不写确定性 ROI 承诺

### 第六章：成功案例参考
- 同类项目实施案例
- 案例来源统一写入“附录C：来源清单”
- 量化成效数据

### 可选扩展章节

以下章节默认不生成，只有用户明确要求“实施方案、实施计划、预算报价、运维方案、投标深化”等内容时启用。

#### 扩展A：实施建议

- 可写阶段建议、推进路径、协同机制
- 表述为“建议”，不得写成正式实施计划、确定工期或交付承诺

#### 扩展B：预算测算框架

| 序号 | 模块名称 | 建设内容 | 金额（万元） |
|------|---------|---------|-------------|
| 1 | {模块1} | {摘要} | 待定 |
| 2 | {模块2} | {摘要} | 待定 |
| | **合计** | | **待定** |

> 注：所有金额标注"待定"，最终报价由商务部门确认。

#### 扩展C：运维运营建议

- 可写运营组织、数据更新、服务保障、持续优化机制
- 涉及人员投入和服务等级时标注待商务和交付团队确认

### 附录A：人工审核提示

```
以下内容需要人工重点审核确认：

1. 政策引用：请核对政策原文，确认文号和引用内容准确
2. 产品匹配：请与产品部门确认方案中提到的产品能力
3. 扩展章节：是否需要补充实施、预算、运维等深化内容
4. 创新亮点：建议由资深顾问补充差异化创新点
5. 客户承诺：方案中的量化指标需确认可达性
6. 竞对策略：如有竞争对手信息，需人工补充应对策略
```

### 附录C：来源清单

```
统一列出政策、行业资料、成功案例的名称、发布单位、时间、来源链接和核验状态。
未能核验原文或缺少来源链接的条目，必须标注“待核验原文”或“待联网核验”。
必须保留“待核查项清单”，列出示例数据、待确认平台名称、待核验政策依据等人工复核项。
```

格式要求：附录A、附录B、附录C必须分别另起一页。
