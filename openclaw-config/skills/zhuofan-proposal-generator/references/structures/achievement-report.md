# 建设情况汇报结构


适用于用户要求“建设情况汇报、工作汇报、成效汇报、阶段性总结、建设成效”等材料。

### 标题

```
关于{项目名称}建设情况的汇报
```

### 开篇总述

写清建设背景、政策/标准依据、建设主线、覆盖范围和总体成效。开篇应有站位、有主线、有结果，例如：

```
自{项目名称}启动建设以来，{地区/单位}围绕{核心主线}，聚焦{企业群众/基层治理/数据共享}堵点痛点，系统推进{若干场景}落地应用，推动{业务}由{传统状态}向{智能化/协同化/便捷化}升级。
```

### 一、建设总体概况

写建设思路、覆盖范围、已建内容和总体指标。建议包含：

- 建设思路：如“标准引领、数据驱动、智能赋能、服务提质”。
- 覆盖范围：大厅、乡镇、街道、部门、平台、终端等。
- 建设成果：已上线系统、服务事项、终端数量、覆盖比例。
- 成效指标：服务人次、时限压缩、满意度、跑动减少、效率提升等。
- 若没有真实运营数据，也要保留指标位，可写“待人工确认”或“示例数据，待人工确认”；正文中必须对该内容添加批注，附录中不加批注。

### 二、场景建设成效

每个场景按以下结构写：

```
场景名称：一句话亮点标题

概述段：说明该场景解决什么问题，实现什么业务转变。

一是{具体做法}。写系统能力、业务动作和量化成效。
二是{具体做法}。写系统能力、业务动作和量化成效。
三是{具体做法}。写系统能力、业务动作和量化成效。
```

正式汇报写法要求：

- “一是、二是、三是”后必须接总结性小标题，小标题加粗并以句号收束，后面再写具体内容。
- 示例：`一是高频事项智能秒批。梳理企业开办、社保登记等高频简易事项，通过规则固化和数据自动比对，实现即来即办、即办即结，累计办结秒批业务450余万件（示例数据，待人工确认）。`
- 每个场景尽量写入2-3个数据口径，如覆盖事项数、终端数、服务人次、办理时长、压缩比例、满意度、评价覆盖率等。数据优先来自材料或联网检索；没有来源时可以先写示例数据，但必须标注待人工确认并在正文添加批注。

候选场景方向可包括，但不得直接当作固定正文：

- 政务服务大厅：智能导航、智能导办、智能问答、秒批秒办、远程审批、智能取号、自动填单、智能表单、智能盖章、智能评价、一件事集成、综窗受理、数据共享、电子证照、自助终端、基层延伸。
- 一网统管：事件协同、领导驾驶舱、城市运行监测、网格治理、联动处置、督查督办、基层减负。
- 数据治理：数据归集、数据共享、数据治理、数据目录、公共数据授权运营、数据安全、数据应用场景。

场景选择规则：

- 优先从用户材料、图片OCR、评分表、需求附件、历史方案、知识库或联网检索结果中提取场景。
- 若用户材料列出场景清单，必须按用户材料逐项展开，不得改写成泛化系统模块。
- 若没有明确场景清单，结合项目主题和检索结果选择 4-7 个最相关场景；无法确认的场景、平台名和数据必须标注待人工确认。正文中的待核查内容添加批注，附录中不加批注。

地方化要求：

- 写入地区名称、县乡村三级服务体系、本地政务服务网/移动端/AI助手名称。
- 本地平台、移动端、AI助手、服务品牌名称必须来自用户材料、知识库或联网检索结果；无法确认时写通用占位并标注待人工确认。
- 平台名称、终端数量、服务人次、满意度等没有来源时，必须标注“待人工确认”；正文中添加批注，附录C中列入待核查项清单。

### 三、下一步工作计划

使用“一是、二是、三是、四是”展开，建议方向：

- 深化智能技术场景应用
- 推进县乡村三级服务体系覆盖
- 强化数据赋能支撑
- 健全地方标准规范
- 完善运营管理和迭代优化机制

### 结尾

总结阶段性成效，承认仍有提升空间，并表态持续迭代完善，服务数字政府建设、营商环境优化或高质量发展大局。
