# 建设方案结构

适用范围：

- 项目需求阶段的建设方案、项目建议支撑材料或方案初稿。
- 面向领导、客户或内部评审，说明“为什么建、要达到什么目标、需求是什么、准备建什么、预期形成什么成效、投资如何估算”。
- 会议纪要、沟通记录、任务安排、需求文档等只是常见输入材料。
- 只有材料内容指向项目建设沟通、立项/评审支撑或需求阶段方案初稿时，才使用本结构。

### 标题

```
{客户单位}{项目名称}建设方案
```

标题规则：

- 标题直接写材料标题，不加书名号《》。
- 标题字体必须为 `方正小标宋_GBK`，字号为二号（22pt）。
- 不得追加“解决方案”“解决方案（初稿）”“（初稿）”等字样。
- 如果项目名称已包含“建设方案”，保持用户/材料中的正式标题。
- 如果项目名称已以“建设”结尾，标题拼接为 `{客户单位}{项目名称}方案`，不得写成“建设建设方案”。

正文字体规则：

- 正文字体必须为 `仿宋_GB2312`，字号为三号（16pt）。
- 正文段落行距为 1.5 倍，首行缩进 2 字符。

文件命名规则：

```
{客户单位}{项目名称}建设方案_{YYYYMMDD}.docx
```

建设方案文件名不得使用内部过程命名或解决方案初稿命名。

## 正文模板

正文主体必须使用以下六个一级标题，顺序不得调整：

```text
一、建设背景

二、建设目标

三、需求分析

四、建设内容

五、建设成效

六、投资估算
```

### 一、建设背景

写作要求：

- 说明项目提出的政策背景、业务背景、现状基础和建设必要性。
- 优先检索并引用与项目直接相关的国家级、省市级、区县级和主题专项政策。
- 资料来源必须按 `references/search/source-web-search.md` 执行检索，并按 `references/search/source-verification.md` 判断核验状态；结果写入 `sections.sources`。
- 政策必须围绕项目建设必要性展开，不做泛泛政策背景铺陈。
- 对于区县项目，应优先体现本地区政府职能转变、营商环境、一网通办、人工智能+政务服务、政策精准推送等直接依据。
- 政策名称、发文单位、文号、发布时间和原文链接必须进入来源清单；无法核验原文链接时标注 `待核验原文` 或 `待联网核验`。
- 正文不得保留 `（来源：xxx）`、`[来源：xxx]`、域名或长链接；对应来源应在来源清单完整列出，需人工核验的来源通过人工审核事项说明。

### 二、建设目标

写作要求：

- 先用一段话说明本项目是在什么既有系统、服务或业务基础上升级。
- 再说明本次建设要达成的目标：页面优化、功能完善、移动端适配、政策匹配、数据互联互通等。
- 对会议纪要中明确出现的目标和范围，应优先原样转为正式表达。
- 不写宏大的“全国领先、标杆示范”等口号，除非用户材料明确要求，且标注待确认。

### 三、需求分析

写作要求：

- 围绕客户现状、服务对象、业务流程、系统能力、数据协同、运营管理等维度分析需求。
- 每项需求应能对应后文建设内容，避免只写抽象问题。
- 对用户材料中已经明确的痛点、诉求和约束，应优先转写为正式项目材料表达。
- 对推断出的需求必须标注 `待确认`，不得写成客户已明确提出。

### 四、建设内容

写作要求：

- 优先抽取会议纪要、需求清单、历史方案中的具体建设项，不要泛化成标准系统模块。
- 按实际建设事项组织，每项采用“事项名称 + 建设动作 + 服务对象/应用场景 + 业务价值”的写法。
- 建设内容下的具体事项使用二级序号，格式为 `（一）事项名称`、`（二）事项名称`、`（三）事项名称`。
- 不显式写“产品匹配”标签，除非用户明确要求内部售前方案。
- 不默认写技术架构、成功案例、实施计划和项目组织。

推荐建设内容颗粒度：

- 页面优化；
- 功能完善；
- 终端或移动端适配；
- 政策匹配；
- 数据互联互通；
- 与第三方平台或本地服务渠道对接。

### 五、建设成效

写作要求：

- 说明建设完成后对服务效率、业务协同、数据共享、用户体验、管理支撑等方面的预期改善。
- 成效必须与建设目标、需求分析和建设内容对应。
- 没有来源或测算依据的量化指标，只能写为建议指标或待测算指标。
- 不写无法核验的承诺性效果。

### 六、投资估算

写作要求：

- 如用户材料提供金额、报价口径或测算依据，可按材料转写并标注来源。
- 如缺少金额依据，应写明投资估算需结合功能范围、建设工作量、软硬件资源、数据对接、部署运维等因素进一步测算。
- 不得虚构金额、单价、周期或商务承诺。

### 来源清单与人工审核事项

写作要求：

- 如正文引用政策、资料、数据或案例，Word 文档末尾应保留“附录A：资料来源链接”，用于人工审核。
- 如正文存在 `待核验`、`待确认`、`待补充`、`待测算`、`需人工审核`、`推断`、`建议`、`未核验` 等内容，Word 文档末尾应保留“附录B：需人工审核事项”。
- 附录只用于承载来源链接、待核验内容和人工审核提示，不作为正文主体章节。
- 附录A和附录B均另起一页。
- 附录A按 `1.`、`2.`、`3.` 数字序号列出来源；每条来源按“来源名称”“原文链接”“支撑内容”分行呈现。
- 附录B按 `1.`、`2.`、`3.` 数字序号列出人工审核事项，不使用 `-` 项目符号。
