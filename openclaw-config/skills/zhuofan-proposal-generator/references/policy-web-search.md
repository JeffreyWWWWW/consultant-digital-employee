# 政策联网检索规则

本规则用于 ZX-01 方案生成时检索和引用政策。目标是减少临场长 query、降低超时概率、避免编造政策。

总原则：凡是要作为方案引用依据的政策、行业资料、统计数据、标准规范、成功案例，只要当前环境具备联网检索能力，就必须先联网检索或查知识库。不得直接凭模型记忆写成已核验来源；检索失败后才允许降级标注。

## 一、检索原则

1. 政策引用必须来自成功检索结果、已知权威原文，或与本项目需求匹配的候选权威政策。
2. `web_search` 返回 timeout、failed、error、no results 时，视为本次联网检索未成功。
3. 检索未成功时，不得声称“已检索到”“根据最新政策”“根据 XX 省/市某政策”。
4. 检索未成功时，不得编造政策名称、发文单位、发文时间、文号或链接。
5. 新闻稿、转载稿、公众号、媒体报道只能作为辅助线索，不得当作政策原文；正文中必须标注 `[待核验原文]`。
6. 优先引用 `gov.cn`、国家部委官网、省/市政府官网、省/市数据局或政务服务主管部门官网。

## 二、必须拆短 query

禁止一次性拼接过长 query，例如：

```
江西省 数字政府建设 政务服务大厅智能化 2024 2025 政策
```

应拆成 3-5 条短 query，每条只解决一个问题：

```
site:jiangxi.gov.cn 数字政府 建设 政策
site:jiangxi.gov.cn 政务服务 标准化 便利化
site:jxzwfww.gov.cn 政务服务 大厅 智能化
site:gov.cn 数字政府建设 指导意见
```

## 三、国家层面候选政策

以下政策仅作为数字政府、数据共享、政务服务、一网统管等场景的国家层面候选依据，不是固定必引清单。生成方案时必须先判断客户需求、项目主题和建设内容是否匹配，再选择引用；不得因为政策常见就默认全量引用。引用时仍应优先标注来源，并在无法打开原文时标注 `[待联网核验]`。

适配原则：

- 数字政府总体规划、政府履职数字化、跨部门协同治理：可考虑《国务院关于加强数字政府建设的指导意见》《数字中国建设整体布局规划》等上位政策。
- 政务数据共享、数据目录、数据治理、跨部门数据协同：可考虑《全国一体化政务大数据体系建设指南》等政务数据体系建设政策。
- 数据要素、公共数据授权运营、数据流通利用：可考虑“数据二十条”等数据基础制度文件。
- 政务服务大厅、一窗受理、标准化便利化：优先检索政务服务标准化、便利化、一体化政务服务平台、行政审批服务改革等相关政策和地方主管部门文件，不应机械套用数据要素政策。
- 一网统管、城市运行、基层治理：优先检索城市运行管理服务平台、基层治理、事件协同处置、地方一网统管相关政策；国家数字政府类政策可作为上位背景补充，不宜替代直接政策依据。

|---|---|---|---|
| 《数字中国建设整体布局规划》 | 中共中央、国务院 | 2023年 | 中国政府网 |
| 《国务院关于加强数字政府建设的指导意见》 | 国务院 | 2022年 | 中国政府网，国发〔2022〕14号 |

## 四、分层检索模板

生成方案前必须完成以下最低检索矩阵，并把每条检索写入 JSON 的 `sections.search_log`。如果某类检索失败，也要在台账中记录 `status: "failed"`，并在正文、附录B或交付说明中降级说明。

| 类别 | 最低要求 | 写入字段 |
|---|---|---|
| 国家政策 | 至少 1 条与主题匹配的国家政策 query | `policy_sources` |
| 省级政策 | 至少 1 条项目所在省份政策 query | `policy_sources` |
| 市级政策 | 至少 1 条项目所在城市政策 query | `policy_sources` |
| 主题政策 | 至少 1 条核心需求主题 query，如一网统管、政务服务、数据共享 | `policy_sources` |
| 行业资料 | 至少 1 条白皮书、标准规范、统计数据或主管部门资料 query | `industry_sources` |
| 成功案例 | 每个拟写入案例至少 1 条单独 query | `cases` |

`search_log` 格式：

```json
[
  {
    "category": "国家政策/省级政策/市级政策/主题政策/行业资料/成功案例",
    "query": "实际执行的检索词",
    "status": "success/partial/no_results/failed/not_run",
    "used_for": "policy_sources/industry_sources/cases",
    "source_names": ["本次检索支撑写入的来源名称"]
  }
]
```

闸门规则：

- 没有 `search_log` 时，不得把政策、行业资料或案例写成已核验。
- 政策正文引用了 `《...》`，但 `policy_sources` 没有对应来源时，必须改为 `[待联网核验]`。
- `cases` 中每个案例必须能在 `search_log` 找到同名或同主题的成功案例检索记录；否则删除该案例，或标注 `待联网核验`。
- `policy_sources`、`industry_sources`、`cases` 为空时，不得在附录B写“检索成功”。
- 降级说明必须区分：`not_run` 未执行检索、`failed` 工具失败、`no_results` 已检索无结果、`partial` 已检索但来源不完整。不得只写“需进一步联网核验”。

## 五、可引用判定

搜索结果只有同时满足以下条件，才能作为正式政策引用：

- 能识别政策名称；
- 能识别发文单位；
- 能识别发文时间或发布日期；
- 来源为政府官网、国家部委官网、政府公报或主管部门官网；
- 与本项目主题确实相关。

不满足上述条件时，正文必须标注：

```
[待核验原文]
```

如果检索失败或未找到可引用政策，正文必须标注：

```
[待联网核验]
```

## 六、正文写法

### 检索成功

```
《国务院关于加强数字政府建设的指导意见》（国务院，2022年）提出，要推进政府治理流程优化、模式创新和履职能力提升，构建数字化、智能化的政府运行新形态，为本项目推进政务服务智能化、数据共享和协同治理提供政策依据。来源详见附录C。
```

### 检索失败

```
国家和地方持续推进数字政府、政务服务标准化便利化、公共数据共享等工作，为本项目建设提供总体方向支撑。相关国家及地方具体政策文件需进一步联网核验后补充。[待联网核验]
```

## 七、生成说明要求

方案“附录B：生成说明”中必须写明政策检索状态：

- `政策检索：成功，引用政策 N 条`
- `政策检索：部分成功，地方政策待核验`
- `政策检索：失败，已按待联网核验降级处理`

检索成功或部分成功时，必须在 JSON 的 `sections.policy_sources` 中附政策来源链接清单：

```json
[
  {
    "name": "政策名称",
    "issuer": "发文单位",
    "date": "发文时间",
    "url": "来源链接",
    "status": "已核验/待核验原文"
  }
]
```

要求：

- `url` 必须来自实际搜索结果或已知权威原文，不得编造。
- `status` 只有在政府官网/部委官网/政府公报原文可确认时才能写 `已核验`。
- 如果只搜到新闻稿、转载稿或二手来源，`status` 必须写 `待核验原文`。
- 如果联网检索失败，`policy_sources` 必须为空数组。

## 八、案例检索要求

成功案例必须优先联网检索或查知识库，不得直接凭模型记忆填写“公开信息/行业案例”。每一个写入方案的案例，都必须针对案例名称或“城市 + 主题 + 案例”执行检索。

推荐按以下方式拆短 query：

```
{城市} {项目关键词} 案例
{项目名称} 官网
{主管单位} {主题关键词}
{城市} 一网统管 案例
```

可作为案例来源的结果包括：

- 政府官网、主管部门官网、运营单位官网；
- 权威媒体报道；
- 公开案例库、厂商公开案例页；
- 招采公告、验收公告、项目新闻等可核验材料。

要求：

- 能找到来源链接时，必须写入 `sections.cases[].url`。
- 案例来源不得只写“公开报道”“公开资料”“网络资料”；只要是联网找到的公开报道或网页，必须写具体 URL。没有 URL 就不能认定为联网检索结果。
- 来源为政府官网、运营单位官网或公开案例库时，`status` 可写 `已核验`。
- 来源为新闻报道、转载稿等二手材料时，`status` 写 `待核验原文`。
- 检索失败或没有链接时，才允许写 `未提供来源链接，不能认定为联网检索结果；请删除该案例或补充实际检索 URL。[待联网核验]`。
- 如果所有案例都检索失败，交付说明必须提示“案例来源待核验”。
- 未执行联网检索或知识库检索时，不得写入成功案例。
