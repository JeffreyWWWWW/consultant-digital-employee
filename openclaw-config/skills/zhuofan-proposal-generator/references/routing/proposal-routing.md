# 交付物类型路由

本文件只负责判断本次用户需要的交付物类型。判断完成后，再根据是否存在对应结构和生成器决定是否继续处理。

当前可用类型：

- `project_report`：项目需求阶段的项目汇报/项目建议支撑材料，读取 `../structures/project-report.md`。

如果没有对应结构或生成器，停止当前交付物处理，先追问或说明当前交付物暂不支持。

## project_report

适用情况：

- 用户明确要求项目汇报、项目建设汇报、项目建议支撑材料、立项依据材料。
- 阶段定位是项目需求阶段。
- 材料内容包含项目背景、建设诉求、建设目标、建设内容、系统优化、功能完善、数据对接、页面优化或适配改造等信息。
- 使用场景服务于项目建设沟通、立项支撑或评审支撑。
- 未明确要求完整技术方案、实施方案、预算、项目组织或投标响应。

不能单独作为判定依据：

- 输入材料类型。
- 泛化交付动作或时间要求。

不得路由为 `project_report`：

- 只是普通材料整理、记录润色、任务清单、工作安排、需求规格说明、培训材料或演示材料。
- 无法判断具体交付物类型或最终用途。
- 用户明确要求完整方案、技术方案、实施方案、投标方案、可研深化、总结汇报或其他非项目需求阶段项目汇报材料。

## 追问规则

- 无法判断交付物类型时，优先追问最终用途、交付对象和期望深度。
- 追问后仍不明确时，不得仅因输入材料形式或交付动作默认路由为 `project_report`。
