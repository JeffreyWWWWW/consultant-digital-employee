# 政策、资料与案例核验规则

本文件用于项目汇报稿中外部依据的检索和核验。目标是避免编造政策、资料、数据和案例。

## 什么时候使用

需要在项目汇报稿中写入以下内容时使用：

- 政策法规、规划文件、标准规范；
- 行业资料、统计数据、白皮书、指南；
- 同类案例、公开报道、建设经验；
- 任何需要作为依据或事实支撑的外部信息。

不需要引用外部依据时，不为了满足流程强行检索。

## 来源原则

- 优先使用政府官网、主管部门官网、标准发布机构、权威公开材料。
- 新闻稿、公众号、转载页只能作为线索，不能直接当作政策原文。
- 找不到原文时，标注 `待核验原文` 或 `待联网核验`。
- 不得编造政策名称、发文单位、发布时间、文号、链接或案例数据。
- 不得把模型记忆写成“已检索”“已核验”。

## 检索要求

- 检索词应拆短，每条 query 只解决一个问题。
- 根据项目区域、客户类型、核心需求生成检索词。
- 引用国家、省市、区县或主题政策时，应分别记录检索过程。
- 写入案例时，应针对案例名称或“区域 + 主题 + 案例”单独检索。

示例：

```text
site:gov.cn {核心需求} 政策
{省/市/区县} {核心需求} 政策
{项目主题} 标准 指南
{区域或同类城市} {项目主题} 案例
```

## search_log 记录

所有检索或核验过程写入 `sections.search_log`：

```json
[
  {
    "category": "政策/资料/案例",
    "query": "实际执行的检索词",
    "status": "success/partial/no_results/failed/not_run",
    "used_for": "写入材料的用途",
    "source_names": ["来源名称"]
  }
]
```

状态说明：

- `success`：找到可用来源。
- `partial`：找到线索，但原文或关键信息不完整。
- `no_results`：已检索但没有结果。
- `failed`：工具失败或网络失败。
- `not_run`：因不需要引用或环境限制未执行检索。

## 写入规则

- 有来源的内容，可以写成已核验依据。
- 只有线索、没有原文时，必须标注待核验。
- 检索失败时，不得写成“根据最新政策”“已依据某文件”。
- 没有 URL 或明确来源时，不得把案例写成已核验案例。
- 交付说明中应提示未核验、待补充或检索失败的内容。
