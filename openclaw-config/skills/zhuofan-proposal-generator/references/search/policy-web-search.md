# 政策、资料与案例检索流程

本文件用于项目汇报稿中外部依据的联网检索。目标是提高找到官网原文的概率，避免把转载、摘要、模型记忆写成已核验来源。

搜索源如何接入和记录，必须同时遵守 `search-provider-integration.md`。来源能否标记为已核验，必须同时遵守 `policy-source-verification.md`。

## 什么时候使用

需要在项目汇报稿中写入以下内容时使用：

- 政策法规、规划文件、标准规范；
- 行业资料、统计数据、白皮书、指南；
- 同类案例、公开报道、建设经验；
- 任何需要作为依据或事实支撑的外部信息。

不需要引用外部依据时，不为了满足流程强行检索。

## 检索总原则

- 搜索工具只负责找线索，不能直接等同于核验。
- 优先找官网原文，再考虑政府公开平台、政府转载、媒体报道。
- 新闻稿、公众号、商业转载页只能作为线索，必须继续反查原文。
- 找不到官网原文时，标注 `待核验原文` 或 `待联网核验`。
- 不得编造政策名称、发文单位、发布时间、文号、链接或案例数据。
- 不得把模型记忆写成“已检索”“已核验”。

## 多源搜索顺序

按以下顺序逐层检索，上一层已经找到并核验官网原文时，可以停止：

1. 官网定向查询
   - `site:` 是搜索语法，不是独立 API 或搜索源；它应写在 `query` 中，不写入 `search_provider`。
   - 先用 Tavily 执行 `site:` 查询，限定国务院、部委、省市区政府官网。
   - 优先用政策标题、文号、发文单位、发布时间组合搜索。

2. Tavily 泛搜
   - 官网定向查询未找到官网原文时，用 Tavily 快速发现标题、转载线索和可能的官网链接。
   - Tavily 找到官网原文且标题、文号、发文单位或发布时间匹配时，`search_provider` 写 `Tavily`。

3. 中文搜索补充
   - Tavily 无结果、只有转载页、只有摘要、结果质量低或工具失败时，按 `search-provider-integration.md` 调用百度搜索补充。
   - 百度应执行同一条 `site:` 查询，并补充中文改写查询，例如“政策标题 + 发文单位”“政策标题 + 文号”“政策标题 + gov.cn”。
   - Tavily 找线索、百度补充反查后共同确认时，`search_provider` 写 `Tavily+百度`。
   - 如果当前环境没有百度搜索工具或 API key，应记录 `not_available`，不得写成已检索。
   - 百度、商业媒体、公众号结果只作为线索，不能直接标记为已核验原文。

4. 转载反查原文
   - 如果只找到转载页，使用转载页标题、文号、发文机关、发布时间继续反查官网原文。
   - 反查仍失败时，保留线索链接并标注 `待核验原文`。

## 检索词生成

检索词应拆短，每条 query 只解决一个问题。根据项目区域、客户类型、核心需求生成检索词。

示例：

```text
site:gov.cn {政策标题或文号}
site:{政府官网域名} {政策标题}
{发文单位} {政策标题}
{政策标题} {文号}
{省/市/区县} {核心需求} 政策
{项目主题} 标准 指南
{区域或同类城市} {项目主题} 案例
```

区县项目建议优先尝试：

```text
site:{区县政府官网域名} {项目主题}
site:{区县政府官网域名} {政策关键词}
site:{市政府官网域名} {项目主题} {区县名称}
```

## 官方域名定向示例

```text
site:gov.cn 国发〔2022〕14号
site:shanghai.gov.cn 人工智能 政务服务 高效办成一件事
site:shhuangpu.gov.cn 政务AI店小二
site:shhuangpu.gov.cn 黄浦区 2025 国民经济和社会发展计划
```

## 检索记录

检索或核验结果写入当前 `document_type` 对应结构要求的来源字段、审核提示或交付说明。没有固定字段要求时，至少记录到 `sections.source_note` 或 `sections.review_notes`。

建议记录以下信息：

```json
[
  {
    "category": "政策/资料/案例",
    "query": "实际执行的检索词",
    "search_provider": "Tavily/百度/Tavily+百度/用户提供",
    "status": "success/partial/no_results/failed/not_run",
    "source_type": "官网原文/政府公开平台/政府转载/媒体转载/线索页/未确认",
    "verification_status": "已核验原文/待核验原文/待联网核验/未找到原文",
    "used_for": "写入材料的用途",
    "source_names": ["来源名称"],
    "source_urls": ["原文链接或线索链接"]
  }
]
```

状态说明：

- `success`：找到来源；是否已核验以 `verification_status` 为准。
- `partial`：找到线索，但原文或关键信息不完整。
- `no_results`：已检索但没有结果。
- `failed`：工具失败或网络失败。
- `not_run`：因不需要引用或环境限制未执行检索。

## 写入规则

- 只有按 `policy-source-verification.md` 判定为已核验原文的内容，才可以写成已核验依据。
- 写入附录A的政策和资料来源应优先使用官网原文链接；找不到原文时可写线索链接，但必须标注待核验。
- 只有线索、没有原文时，必须进入附录B人工审核事项。
- 检索失败时，不得写成“根据最新政策”“已依据某文件”。
- 没有 URL 或明确来源时，不得把案例写成已核验案例。
- 交付说明中应提示未核验、待补充或检索失败的内容。
