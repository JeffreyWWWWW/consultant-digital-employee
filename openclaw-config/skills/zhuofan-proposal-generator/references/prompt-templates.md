# 资深顾问提示词模板

本文件沉淀了资深咨询顾问的写作经验，供方案生成时参考。

## 一、通用润色提示词

### 1.1 专业化润色
当方案初稿生成后，按以下标准进行润色：
- 删除所有重复表达和无关修饰词
- 将口语化表达转为书面政府公文风格
- 确保每个段落只表达一个核心观点
- 使用"统筹推进"、"深化应用"、"集约建设"等术语替代白话

### 1.2 逻辑重构
方案逻辑必须遵循闭环：
```
现状分析 → 痛点梳理 → 建设目标 → 总体架构 → 建设内容 → 需求边界 → 价值收益
```
检查清单：
- 痛点与建设内容是否一一对应
- 建设内容是否支撑总体目标
- 需求边界、事项范围、服务渠道和目标用户是否说清楚
- 是否避免写成实施计划、报价或交付承诺

### 1.3 精简压缩
将冗长段落压缩为精炼表述：
- 每个要点控制在 2-3 句话
- 用数据替代形容词（"大幅提升" → "提升 40%"）
- 删除"值得注意的是"、"不可否认"等过渡废话

## 二、场景化写作要领

### 2.1 面向政务服务中心（默认）
**写作要求：**
- 以项目需求阶段为默认语境，重点写需求背景、业务痛点、事项范围、服务渠道和群众体验
- 聚焦政务大厅、综窗受理、智能导办、智能问答、智能表单、自助终端、基层延伸、评价监督等服务场景
- 多用“提升办事便利度”“压缩办理时限”“减少重复填报”“推动线上线下融合”“优化窗口运行效率”等表达
- 不默认写实施排期、项目组织和预算报价；如需深化，作为扩展章节处理

**结构模板：**
```
一、现状分析
二、建设目标
三、建设内容
四、技术架构
五、方案亮点与预期效益
六、成功案例参考
```

### 2.2 向数据局/政务办汇报
**写作要求：**
- 政治站位要高，体现对上级政策的贯彻落实
- 多用"根据XX文件精神"、"按照XX部署要求"开头
- 成效用量化数据："累计办理XX万件"、"群众满意度达XX%"
- 突出"降本增效"、"数据共享"、"基层减负"、"营商环境优化"
- 结尾提下一步计划，体现持续推进的决心

**结构模板：**
```
一、工作背景与政策依据
二、建设现状与主要成效
三、存在问题与不足
四、下一步工作计划
  （一）……
  （二）……
  （三）……
```

### 2.3 规划方案/可行性研究
**写作要求：**
- 注重顶层设计的系统性和前瞻性
- 技术路线清晰，架构图完整
- 项目需求阶段初稿默认不写投资估算；用户明确要求可研深化时，才作为扩展章节补充测算依据
- 风险分析默认写风险边界和待确认项；用户要求可研深化时再展开应对措施
- 信创要求时必须标注国产化替代方案

**深化扩展结构模板（仅在用户明确要求可研/实施深化时使用）：**
```
一、项目概述
  1.1 建设背景
  1.2 建设目标
  1.3 建设范围
二、现状分析
三、需求分析
四、总体设计
  4.1 设计原则
  4.2 总体架构
  4.3 技术路线
五、详细设计（分模块）
六、实施建议
七、投资估算（待商务/咨询测算确认）
八、效益分析
九、风险评估与应对
```

### 2.4 面向数据集团/业主
**写作要求：**
- 强调落地性和可操作性
- 投资价值分析，避免写确定性 ROI 承诺
- 商业模式设计（政府购买服务 vs 企业增值服务 vs 特许经营）
- 项目需求阶段初稿默认不写分期实施路径；用户明确要求深化时，可作为扩展章节写“实施建议”
- 运营方案和可持续发展策略默认写为价值建议，进入深化阶段后再展开

### 2.5 面向企业客户
**写作要求：**
- 聚焦业务价值和场景
- 少讲政策多讲效果
- 效率提升的量化数据
- 与现有系统的集成方案
- 实施风险和兜底措施仅在用户要求实施深化或投标响应时展开

## 三、去 AI 化处理规则

### 3.1 必须删除的表达
| 类别 | AI 典型表达 | 替换为 |
|------|-----------|--------|
| 开头套话 | "在当今数字化转型的浪潮中" | 直接切入政策或现状 |
| 过渡废话 | "综上所述"、"总而言之" | 删除，直接写结论 |
| 万能形容 | "全方位"、"一站式"、"赋能" | 用具体功能或数据替代 |
| 虚假谦逊 | "仅供参考"、"不成熟的建议" | 删除 |
| 身份暴露 | "作为AI"、"我是语言模型" | 删除 |
| 堆砌排比 | 连续三个以上"通过XX，实现XX" | 保留最有力的 1-2 个 |

### 3.2 润色检查清单
- [ ] 全文无"综上所述"、"总而言之"
- [ ] 全文无"全方位"、"一站式"（除非是产品名）
- [ ] 全文无"赋能千行百业"类空话
- [ ] 每段有实质性内容或数据支撑
- [ ] 政策引用有具体文号和来源
- [ ] 产品名称与公司产品清单一致

## 四、投标文件优化要领

### 4.1 整体润色
- 确保技术方案与招标要求逐条对应
- 评分项逐一核对，确保无遗漏
- 方案亮点前置，让评委快速抓到核心价值

### 4.2 分模块优化
每个功能模块的描述结构：
```
[模块名称]
1. 建设目标：解决什么问题
2. 功能设计：包含哪些子功能
3. 技术实现：关键技术方案
4. 产品支撑：对应公司产品
5. 预期效果：量化指标
```

### 4.3 响应函优化
- 逐条响应，不漏项
- 有偏离的主动说明并提出替代方案
- 正偏离（超出要求）突出展示
