# 方案标准结构模板

本文件定义方案初稿的标准章节结构和各章节写作规范。

## 文档类型路由

- 解决方案、建设方案、项目方案、方案初稿：使用“标准七章结构”。
- 建设情况汇报、工作汇报、成效汇报、阶段总结：使用“建设情况汇报结构”。
- 汇报型材料重点写“已建成什么、取得什么成效、下一步怎么做”，不得硬套七章解决方案。

## 标准七章结构

### 元信息区

```
《{项目名称}》解决方案（初稿）

编制单位：卓繁信息集团股份有限公司
目标客户：{客户单位全称}
客户类型：{数据局/政务中心/大数据中心/数据集团/企业}
编制日期：{YYYY年MM月DD日}
版  本：V0.1（AI辅助生成初稿）
```

### 第一章：现状分析

#### 1.1 政策背景

**写作要求：**
- 按国家级 → 省级 → 市级三级梳理相关政策
- 每条政策标注：政策全称、发文单位、发文时间/文号
- 说明政策对本项目的指导意义

**候选政策来源：**
- 国家层面：根据项目主题选择数字政府、政务服务、政务大数据、数据要素、城市运行等相关政策，不得固定套用。
- 省级层面：按项目所在地和主题检索数字政府建设规划、政务服务改革、公共数据管理、数据条例等文件。
- 市级层面：按客户需求检索智慧城市、一网统管、政务服务大厅、数据共享、基层治理等相关方案或管理办法。

**格式示例（仅在项目主题匹配并能核验来源时使用）：**
```
2023年2月，中共中央、国务院印发《数字中国建设整体布局规划》，明确提出
"到2025年，基本形成横向打通、纵向贯通、协调有力的一体化推进格局"，
为{区域}数字政府建设指明了方向。来源详见附录C。
```

#### 1.2 现状概述

**写作要求：**
- 客观描述目标客户当前信息化建设水平
- 已有的信息化系统和平台
- 取得的阶段性成果
- 如无具体信息，按行业通用水平描述，并在附录B“内容来源说明”中提示需人工审核

#### 1.3 痛点问题

**写作要求：**
- 列出 3-5 个核心痛点
- 使用"一是……二是……三是……"句式
- 每个痛点都必须在第三章"建设内容"中有对应的解决方案
- 痛点描述要具体，避免空泛

**格式示例：**
```
一是数据孤岛问题突出。各部门业务系统独立建设，数据标准不统一，
  跨部门数据共享交换困难，导致"数据多跑路、群众少跑腿"难以落地。

二是城市运行管理缺乏统一平台。各条线管理系统分散，事件处置流程
  不畅，跨部门协同效率低，缺少统一的城市运行态势感知能力。

三是……
```

### 第二章：建设目标

#### 2.1 总体目标

**写作要求：**
- 一段话概括项目整体建设目标
- 包含可量化的指标（效率提升XX%、覆盖率达XX%等）
- 体现与国家/省级政策的呼应

#### 2.2 分项目标

**写作要求：**
- 与 1.3 痛点一一对应
- 每个痛点对应一个建设目标
- 目标可衡量、可检验

---

### 第三章：建设内容

#### 3.1 ~ 3.N 各模块

**每个模块的标准描述结构：**

```
3.X {模块名称}

（1）建设目标
    简述本模块解决的核心问题，呼应第一章痛点。

（2）功能设计
    分条列出主要功能点：
    - 功能A：描述
    - 功能B：描述
    - 功能C：描述

（3）【产品匹配】
    对应卓繁产品：{产品名称}
    （如无法确认，标注"待确认——需与产品部门核实"）

（4）预期效果
    量化指标：{具体数据}
```

### 第四章：技术架构

#### 4.1 总体架构

├─────────────────────────────────────┤

│  统一身份认证/工作流引擎/消息中心      │
├──────────────┬──────────────────────┤

#### 4.2 技术选型

**写作要求：**
- 列出核心技术组件的选型建议
- 有信创要求时标注国产化替代方案
- 说明选型理由

### 第五章：实施计划

#### 5.1 分期路径

**标准三期描述：**

| 阶段 | 时间 | 建设内容 | 交付物 |
|------|------|---------|--------|
| 一期（基础建设） | X个月 | 核心平台搭建 | 平台上线 |
| 二期（深化应用） | X个月 | 业务系统对接 | 全面推广 |
| 三期（优化提升） | X个月 | 智能化升级 | 运营优化 |

#### 5.2 项目组织

**标准项目组织架构：**
- 项目领导小组
- 项目管理办公室（PMO）
- 技术实施团队
- 业务配合团队

### 第七章：亮点与预期效益

#### 7.1 方案亮点
- 列出 3-5 个差异化亮点
- 突出技术创新、管理创新、模式创新

#### 7.2 预期效益
- 量化指标：效率提升、覆盖率、成本节约
- 社会效益：群众满意度、政务透明度
- 经济效益：预估投资回报

#### 7.3 成功案例
- 同类项目实施案例
- 案例来源统一写入“附录C：来源清单”
- 量化成效数据

### 附录A：人工审核提示

```
以下内容需要人工重点审核确认：

1. 政策引用：请核对政策原文，确认文号和引用内容准确
2. 产品匹配：请与产品部门确认方案中提到的产品能力
3. 预算金额：请商务部门填写具体金额
4. 创新亮点：建议由资深顾问补充差异化创新点
5. 客户承诺：方案中的量化指标需确认可达性
6. 竞对策略：如有竞争对手信息，需人工补充应对策略
```

### 附录B：生成说明

```
本方案初稿由「咨询顾问-卓智」数字员工辅助生成。

生成参数：
- 客户类型：{customer_type}
- 区域：{region}
- 行业：{industry}
- 核心需求：{requirement}

内容来源：
- 知识库检索：{N}条相关内容
- 政策引用：{N}条（来源详见“附录C：来源清单”）
- 内容来源说明：政策来源、行业资料、案例来源详见来源清单；其余内容为模型辅助生成，需人工审核确认。

声明：本方案初稿需经人工审核确认后方可对外使用。
```

### 附录C：来源清单

```
统一列出政策、行业资料、成功案例的名称、发布单位、时间、来源链接和核验状态。
未能核验原文或缺少来源链接的条目，必须标注“待核验原文”或“待联网核验”。
必须保留“待核查项清单”，列出示例数据、待确认平台名称、待核验政策依据等人工复核项。
```

格式要求：附录A、附录B、附录C必须分别另起一页。

## 建设情况汇报结构

适用于用户要求“建设情况汇报、工作汇报、成效汇报、阶段性总结、建设成效”等材料。

### 标题

```
关于{项目名称}建设情况的汇报
```

### 开篇总述

写清建设背景、政策/标准依据、建设主线、覆盖范围和总体成效。开篇应有站位、有主线、有结果，例如：

```
自{项目名称}启动建设以来，{地区/单位}围绕{核心主线}，聚焦{企业群众/基层治理/数据共享}堵点痛点，系统推进{若干场景}落地应用，推动{业务}由{传统状态}向{智能化/协同化/便捷化}升级。
```

### 一、建设总体概况

写建设思路、覆盖范围、已建内容和总体指标。建议包含：

- 建设思路：如“标准引领、数据驱动、智能赋能、服务提质”。
- 覆盖范围：大厅、乡镇、街道、部门、平台、终端等。
- 建设成果：已上线系统、服务事项、终端数量、覆盖比例。
- 成效指标：服务人次、时限压缩、满意度、跑动减少、效率提升等。
- 若没有真实运营数据，也要保留指标位，可写“待人工确认”或“示例数据，待人工确认”；生成 Word 时必须对该内容添加批注。

### 二、场景建设成效

每个场景按以下结构写：

```
场景名称：一句话亮点标题

概述段：说明该场景解决什么问题，实现什么业务转变。

一是{具体做法}。写系统能力、业务动作和量化成效。
二是{具体做法}。写系统能力、业务动作和量化成效。
三是{具体做法}。写系统能力、业务动作和量化成效。
```

候选场景方向可包括，但不得直接当作固定正文：

- 政务服务大厅：智能导航、智能导办、智能问答、秒批秒办、远程审批、智能取号、自动填单、智能表单、智能盖章、智能评价、一件事集成、综窗受理、数据共享、电子证照、自助终端、基层延伸。
- 一网统管：事件协同、领导驾驶舱、城市运行监测、网格治理、联动处置、督查督办、基层减负。
- 数据治理：数据归集、数据共享、数据治理、数据目录、公共数据授权运营、数据安全、数据应用场景。

场景选择规则：

- 优先从用户材料、图片OCR、评分表、需求附件、历史方案、知识库或联网检索结果中提取场景。
- 若用户材料列出场景清单，必须按用户材料逐项展开，不得改写成泛化系统模块。
- 若没有明确场景清单，结合项目主题和检索结果选择 4-7 个最相关场景；无法确认的场景、平台名和数据必须标注待人工确认并添加批注。

地方化要求：

- 写入地区名称、县乡村三级服务体系、本地政务服务网/移动端/AI助手名称。
- 本地平台、移动端、AI助手、服务品牌名称必须来自用户材料、知识库或联网检索结果；无法确认时写通用占位并标注待人工确认。
- 平台名称、终端数量、服务人次、满意度等没有来源时，必须标注“待人工确认”，生成 Word 时必须添加批注。

### 三、下一步工作计划

使用“一是、二是、三是、四是”展开，建议方向：

- 深化智能技术场景应用
- 推进县乡村三级服务体系覆盖
- 强化数据赋能支撑
- 健全地方标准规范
- 完善运营管理和迭代优化机制

### 结尾

总结阶段性成效，承认仍有提升空间，并表态持续迭代完善，服务数字政府建设、营商环境优化或高质量发展大局。
