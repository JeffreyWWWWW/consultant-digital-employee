# 项目汇报质量检查清单

适用于 `document_type: "project_report"`。

## 结构与标题

- [ ] 标题直接写材料标题，不加书名号《》。
- [ ] 标题字体为 `方正小标宋_GBK` 二号（22pt）。
- [ ] 正文字体为 `仿宋_GB2312` 三号（16pt）。
- [ ] 正文段落行距为 1.5 倍，首行缩进 2 字符。
- [ ] Word 文档已写入上述字体名称和字号。
- [ ] 标题不得包含“解决方案”“解决方案（初稿）”“（初稿）”。
- [ ] 标题应体现客户单位、项目名称和“汇报”。
- [ ] 项目名称以“建设”结尾时，标题和文件名不得出现“建设建设项目汇报”。
- [ ] 正文一级标题使用中文序号：`一、项目建设的依据`、`二、建设目标`、`三、建设内容`。
- [ ] 正文内部不得重复使用 `一、`、`二、`、`三、` 一级章序号；项目建设依据内部层次应使用 `（一）`、`（二）`、`（三）`。
- [ ] 建设内容下的具体事项使用二级序号：`（一）`、`（二）`、`（三）`。
- [ ] 正文主体只包含“项目建设的依据、建设目标、建设内容”三类内容。
- [ ] 文末保留“附录A：政策与资料来源链接”和“附录B：需人工审核事项”。
- [ ] 附录A和附录B均另起一页。
- [ ] 未默认生成技术架构、成功案例、预算、实施计划、项目组织等方案扩展内容。
- [ ] 文件名使用 `{客户单位}{项目名称}建设项目汇报_{YYYYMMDD}.docx`，不得使用内部过程命名或解决方案初稿命名。

## 政策依据

- [ ] 政策依据围绕项目建设必要性展开，不做泛泛政策背景。
- [ ] 资料来源已按 `references/search/policy-web-search.md` 检索和核验，并写入 `sections.policy_sources` 或等价来源字段。
- [ ] 已优先检索国家、省市、区县、主题专项政策。
- [ ] 区县项目体现本地政府职能转变、营商环境、一网通办、人工智能+政务服务、政策精准推送等直接依据。
- [ ] 每条政策说明对本项目的支撑关系。
- [ ] 政策名称、来源机构、文号/发布时间和原文链接或核验状态已进入附录A。
- [ ] 已找到原文链接的政策和资料已在附录A附上链接。
- [ ] 正文未保留 `（来源：xxx）`、域名或长链接；来源信息已进入附录A，需核验来源通过附录B对应批注说明。
- [ ] 附录A使用 `1.`、`2.`、`3.` 数字序号，并按名称、原文链接、支撑内容分行呈现。
- [ ] 附录A每条来源均包含政策/资料名称、原文链接或核验状态、支撑内容；不得只给未审查的来源清单。
- [ ] 附录A每条来源均已审查：未明确标注 `已核验原文`、`人工已核验原文` 或 `已核验官网原文` 的来源，均已进入附录B人工审核事项并有对应正文批注。
- [ ] 未核验的政策标注 `待核验原文` 或 `待联网核验`，不得写成已核验。

## 建设目标

- [ ] 建设目标来自会议纪要、任务安排、需求清单或用户明确要求。
- [ ] 写清是在什么既有系统或服务基础上升级。
- [ ] 覆盖页面优化、功能完善、移动端适配、政策匹配、数据互联互通等实际目标。
- [ ] 不写“全国领先、标杆示范”等宏大口号，除非用户材料明确要求并标注待确认。

## 建设内容

- [ ] 优先抽取会议纪要、需求清单、历史方案中的具体建设项。
- [ ] 未泛化成标准系统模块或六章解决方案模块。
- [ ] 每项采用“事项名称 + 建设动作 + 业务价值”的写法。
- [ ] 不显式写“产品匹配”标签，除非用户明确要求内部售前方案。
- [ ] 未虚构产品能力、实施周期、金额或承诺性指标。

## 交付说明

- [ ] 最后一条交付说明简洁说明文件已生成。
- [ ] 交付说明和过程提示使用中文，未输出 `Now let me...`、`Let me...`、`I need to...`、`The issue is...` 等英文内部流程句。
- [ ] 未把检查代码、匹配 target、修复引号、生成 JSON、调用脚本等内部执行过程写入对话。
- [ ] 不在对话中展开材料全文或完整检查清单。
- [ ] 来源链接、待核验内容和人工审核提示已分别写入 Word 文档附录A和附录B。
- [ ] 附录B开头已说明批注内容均需人工核对。
- [ ] 附录B人工审核事项使用 `1.`、`2.`、`3.` 数字序号，不使用 `-` 项目符号。
- [ ] 附录B条目本身不重复添加批注；批注应挂到前文对应正文段落。
- [ ] 正文中需人工核查的 `待核验`、`待确认`、`待补充`、`待测算`、`需人工审核`、`需人工复核`、`推断`、`建议`、`未核验`、`模型生成`、`模型建议` 内容已进入 `sections.review_notes`，不额外生成游离批注。
- [ ] 模型根据材料推断、补写或无法从来源直接证明的正文片段已写入 `sections.review_highlights` 或 `sections.manual_review_terms`，并在 `sections.review_notes` 中有对应编号审核项。
- [ ] 附录B每条人工审核事项均已在前文对应正文段落添加 Word 批注；不存在只列在附录B、未对应正文批注的审核事项。
- [ ] Word 批注数量与附录B编号事项数量完全一致，批注文本按 `附录B第N项` 对应。
- [ ] 附录B涉及政策原文链接待核验时，如附录A已有原文链接，对应批注已带上该链接。
- [ ] `sections.review_notes` 每条均提供准确 `target` 或 `match_text`；生成器未报“必须对应前文正文批注”错误。
