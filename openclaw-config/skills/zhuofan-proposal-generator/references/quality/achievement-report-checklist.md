# 建设情况汇报质量检查清单

适用于 `document_type: "achievement_report"`。

## 结构完整性

- [ ] 标题无重复词，如不得出现“建设建设情况”。
- [ ] 包含“建设总体概况、场景建设成效、下一步工作计划、结尾”。
- [ ] 场景建设成效来自用户材料、图片 OCR、需求附件、知识库或联网检索结果。
- [ ] 未把候选场景清单机械写成固定正文。

## 内容准确性

- [ ] 总体概况包含覆盖范围、终端数量、事项覆盖率、服务人次、时限压缩、满意度等指标位。
- [ ] 示例数据已逐项标注“示例数据，待人工确认”，并在正文添加 Word 批注。
- [ ] 正文中的待人工核查、待人工确认、待人工补充、待联网核验、待核验原文、待确认、待补充内容均已添加 Word 批注；附录A/B/C不添加批注。
- [ ] 地方平台名称、服务品牌、AI助手名称等已优先通过材料或联网检索核验；无法确认的已标注待人工确认。

## 语言风格

- [ ] 每个场景体现“业务动作 + 系统能力 + 量化结果”。
- [ ] 场景成效和下一步计划采用“加粗小标题 + 正文说明”格式，如“一是高频事项智能秒批。……”。
- [ ] 全文无“综上所述”“总而言之”“全方位保障”“一站式服务”“赋能千行百业”等套话。
- [ ] 无 emoji 符号。
- [ ] 符合正式汇报材料风格。

## 来源追溯

- [ ] 政策、行业资料、成功案例均在“附录C：来源清单”中列明链接或核验状态。
- [ ] 附录C保留“待核查项清单”，列出示例数据、待确认平台名称、待核验政策依据等人工复核项。
- [ ] 交付说明中说明政策和案例来源详见“附录C：来源清单”。
