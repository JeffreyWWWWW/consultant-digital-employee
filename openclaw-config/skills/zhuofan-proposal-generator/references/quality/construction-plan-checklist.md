# 建设方案质量检查清单

适用于 `document_type: "construction_plan"`，用户可见交付物名称为“建设方案”。

## 结构与标题

- [ ] 标题直接写材料标题，不加书名号《》。
- [ ] 标题字体为 `方正小标宋_GBK` 二号（22pt）。
- [ ] 正文字体为 `仿宋_GB2312` 三号（16pt）。
- [ ] 正文段落行距为 1.5 倍，首行缩进 2 字符。
- [ ] Word 文档已写入上述字体名称和字号。
- [ ] 标题不得包含“解决方案”“解决方案（初稿）”“（初稿）”。
- [ ] 标题应体现客户单位、项目名称和“建设方案”。
- [ ] 项目名称以“建设”结尾时，标题和文件名不得出现“建设建设方案”。
- [ ] 正文一级标题使用中文序号：`一、建设背景`、`二、建设目标`、`三、需求分析`、`四、建设内容`、`五、建设成效`、`六、投资估算`。
- [ ] 正文内部不得重复使用 `一、`、`二、`、`三、` 等一级章序号；内部层次应使用 `（一）`、`（二）`、`（三）`。
- [ ] 建设内容下的具体事项使用二级序号：`（一）`、`（二）`、`（三）`。
- [ ] 正文主体只包含“建设背景、建设目标、需求分析、建设内容、建设成效、投资估算”六类内容。
- [ ] 文件名使用 `{客户单位}{项目名称}建设方案_{YYYYMMDD}.docx`，不得使用内部过程命名或解决方案初稿命名。

## 建设背景

- [ ] 建设背景围绕政策背景、业务背景、现状基础和建设必要性展开。
- [ ] 资料来源已按 `references/search/source-web-search.md` 检索，并按 `references/search/source-verification.md` 判断核验状态；结果已写入 `sections.sources`。
- [ ] 已优先检索国家、省市、区县、主题专项政策。
- [ ] 每条政策说明对本项目的支撑关系。
- [ ] 政策名称、来源机构、文号/发布时间和原文链接或核验状态已进入来源清单。
- [ ] 正文未保留 `（来源：xxx）`、域名或长链接；来源信息已进入来源清单，需核验来源通过人工审核事项说明。

## 建设目标

- [ ] 建设目标来自会议纪要、任务安排、需求清单或用户明确要求。
- [ ] 写清是在什么既有系统、服务或业务基础上升级。
- [ ] 覆盖页面优化、功能完善、移动端适配、政策匹配、数据互联互通等实际目标。
- [ ] 不写“全国领先、标杆示范”等宏大口号，除非用户材料明确要求并标注待确认。

## 需求分析

- [ ] 需求分析围绕客户现状、服务对象、业务流程、系统能力、数据协同、运营管理等维度展开。
- [ ] 每项需求能对应后文建设内容。
- [ ] 用户材料中的明确痛点、诉求和约束已优先转写。
- [ ] 推断出的需求已标注 `待确认`。

## 建设内容

- [ ] 优先抽取会议纪要、需求清单、历史方案中的具体建设项。
- [ ] 未泛化成标准系统模块。
- [ ] 每项采用“事项名称 + 建设动作 + 服务对象/应用场景 + 业务价值”的写法。
- [ ] 不显式写“产品匹配”标签，除非用户明确要求内部售前方案。
- [ ] 未虚构产品能力、实施周期、金额或承诺性指标。

## 建设成效

- [ ] 建设成效与建设目标、需求分析和建设内容对应。
- [ ] 成效围绕服务效率、业务协同、数据共享、用户体验、管理支撑等方面展开。
- [ ] 没有来源或测算依据的量化指标已写为建议指标或待测算指标。
- [ ] 未写无法核验的承诺性效果。

## 投资估算

- [ ] 用户材料提供金额、报价口径或测算依据时，已按材料转写并标注来源。
- [ ] 缺少金额依据时，已说明需结合功能范围、建设工作量、软硬件资源、数据对接、部署运维等因素进一步测算。
- [ ] 未虚构金额、单价、周期或商务承诺。

## 交付说明

- [ ] 最后一条交付说明简洁说明文件已生成。
- [ ] 交付说明和过程提示使用中文，未输出 `Now let me...`、`Let me...`、`I need to...`、`The issue is...` 等英文内部流程句。
- [ ] 未把检查代码、匹配 target、修复引号、生成 JSON、调用脚本等内部执行过程写入对话。
- [ ] 不在对话中展开材料全文或完整检查清单。
- [ ] 来源链接、待核验内容和人工审核提示已按需写入 Word 文档附录A和附录B。
- [ ] 如存在附录B人工审核事项，正文对应段落已添加 Word 批注。
